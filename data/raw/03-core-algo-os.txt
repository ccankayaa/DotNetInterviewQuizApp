core~basic~Big-O ve amortized analiz~Big-O and amortized analysis~Big-O girdiye göre asimptotik üst büyüme sınırı verir; amortized analiz işlem dizisi maliyetini yayar.~Big-O describes an asymptotic upper growth bound; amortized analysis spreads cost across an operation sequence.~Önce veri boyutu ve erişim desenini tanımla; O(1) amortized ile worst-case'i ayır.~Define input scale and access patterns; distinguish amortized O(1) from worst case.~Big-O'nun gerçek işlem süresini veya bellek erişim maliyetini tek başına belirlediğini sanma.~Do not assume Big-O alone predicts wall time or memory-access costs.~Asimptotik garanti ölçeklenmeyi açıklar; sabit katsayı ve cache yerelliği gerçekte önemlidir.~Asymptotics explain scaling; constants and cache locality matter in practice.~Girdi büyüklüğüne karşı süre ve allocation eğrilerini benchmark et.~Benchmark time and allocations as input size grows.
core~intermediate~CPU cache ve locality~CPU cache and locality~CPU önbellekleri yakın zamanda ve yakın adreste kullanılan veriyi daha hızlı getirir.~CPU caches retrieve recently and spatially nearby data faster than main memory.~Bitişik veri yerleşimini ve uygun erişim sırasını profil ile doğrula.~Use profiling to validate contiguous layouts and access order.~Pointer-chasing linked list'in array'den her zaman daha hızlı olduğunu sanma.~Do not assume pointer-chasing linked lists always outperform arrays.~Cache-local veri bazen daha iyi teorik Big-O'yu pratikte geçebilir.~Cache-local data may beat an algorithm with better theoretical Big-O in practice.~Cache miss, branch misprediction ve perf counter verilerine bak.~Inspect cache misses, branch mispredictions, and performance counters.
core~intermediate~Compiler ve interpreter~Compilers and interpreters~Derleyici kaynak kodu ara temsile ya da makine koduna dönüştürür; yorumlayıcı yürütme stratejisidir.~A compiler transforms source into an intermediate representation or machine code; interpretation is an execution strategy.~Dil ile çalışma zamanı yürütme stratejisini birbirine karıştırmadan değerlendirme yap.~Assess the language separately from its runtime execution strategy.~JIT ile yorumlamayı aynı kavram veya tüm dinamik dilleri yorumsal kabul etme.~Do not equate JIT with interpretation or assume every dynamic language is interpreted.~Ahead-of-time derleme başlangıca yarar sağlayabilir; JIT dinamik profilden yararlanabilir.~AOT can improve startup while JIT may exploit runtime profiling.~Başlangıç süresi, steady-state CPU ve generated code'u ölç.~Measure startup, steady-state CPU, and generated code.

core~intermediate~UTF-8 ve Unicode~UTF-8 and Unicode~Unicode code point tanımlar; UTF-8 değişken uzunlukta encoding'dir; grapheme cluster tek görsel karakter olabilir.~Unicode defines code points; UTF-8 is variable-width encoding; one grapheme cluster can be visually one character.~Kullanıcı görünen metinde grapheme farkını gözet; byte slicing ile Unicode karakter kesme.~Respect grapheme clusters for user-facing text; avoid slicing Unicode by arbitrary bytes.~Bir karakterin daima bir byte veya bir UTF-16 code unit olduğunu düşünme.~Do not assume a character always occupies one byte or one UTF-16 code unit.~UTF-8 ağda verimlidir ama indeks ve uzunluk semantiği özen ister.~UTF-8 is network-efficient but length and indexing require care.~Emoji, combining mark ve Türkçe yerel harflerle test et.~Test emoji, combining marks, and Turkish characters.

core~intermediate~Serialization formatları~Serialization formats~JSON metin tabanlıdır; Protobuf şema tabanlı binary kodlama sunar, her ikisi sürüm ve uyumluluk disiplinine ihtiyaç duyar.~JSON is textual; Protobuf uses schema-based binary encoding, and both require versioning discipline.~Sözleşme evrimini eski/yeni okuyucu testleri ve gerçek payload'larla doğrula.~Validate schema evolution with old/new reader tests and real payloads.~Alan numaralarını Protobuf'da yeniden kullanma veya JSON ad değişimini risksiz sayma.~Never reuse Protobuf field numbers or assume JSON renaming is risk-free.~İnsan okunabilirliği ile payload boyutu ve şema kontrolü arasında seçim yapılır.~The choice trades human readability against payload size and schema enforcement.~Payload byte boyutu, decode CPU ve compatibility testlerini izle.~Measure payload bytes, decode CPU, and compatibility tests.
core~advanced~False sharing~False sharing~Ayrı thread'lerin aynı CPU cache line'daki farklı değişkenleri yazması coherence trafiğini yükseltebilir.~Threads writing distinct variables on one CPU cache line may cause coherence traffic.~Counter düzeni ve per-thread aggregation'ı benchmark et; ölçüm olmadan padding ekleme.~Benchmark counter layout and per-thread aggregation before padding blindly.~Farklı değişkene yazıldığı için cache line çatışması asla olmaz düşünme.~Do not assume distinct variables cannot interfere through the same cache line.~Hizalama ve padding contention azaltabilir fakat bellek ayak izini büyütür.~Alignment and padding can reduce contention but increase memory footprint.~Thread sayısına göre throughput ve cache coherence event'lerini incele.~Inspect throughput versus thread count and cache-coherence events.
core~intermediate~Endianness~Endianness~Endianness çok byte'lı sayıların bellekte veya protokolde hangi byte sırasıyla saklandığını belirler.~Endianness defines the byte order of multibyte numbers in memory or protocols.~Ağ protokollerinde byte order dönüşümünü açık ve test edilebilir yap.~Make network byte-order conversions explicit and testable.~Makine byte sırasının tüm platformlarda aynı olduğunu varsayma.~Do not assume host byte order is identical across platforms.~Yerel temsil hızlı olabilir ama wire format taşınabilirlik ister.~Native representation is fast but wire formats require portability.~Hex dump ve cross-platform round-trip testleri kullan.~Use hex dumps and cross-platform round-trip tests.
core~advanced~İşletim sistemi ile uygulama sınırı~User mode versus kernel mode~User mode süreçleri kernel çağrılarına kontrollü syscall arayüzüyle geçer; izolasyon güvenlik için kritiktir.~User-mode processes enter kernel services through controlled syscalls; isolation is central to security.~Dosya ve ağ I/O maliyetini sistem çağrısı ve context switch açısından incele.~Inspect file/network I/O costs in terms of syscalls and context switches.~Her fonksiyon çağrısının kernel mode'a geçtiğini düşünme.~Do not assume every function call switches into kernel mode.~Koruma sınırı güvenliği artırır ama geçiş maliyetine sahiptir.~Protection boundaries improve security but have crossing costs.~Syscall sayısı, CPU kernel yüzdesi ve context switch ölç.~Measure syscall count, kernel CPU share, and context switches.
core~intermediate~CAP ile ACID farkı~CAP versus ACID~ACID tek transaction garantilerini; CAP ağ bölünmesi varken dağıtık tutarlılık ve erişilebilirlik tercihini anlatır.~ACID describes transaction guarantees; CAP addresses consistency versus availability under partitions.~Transaction izolasyonu ile çok düğümlü veri erişim politikasını ayrı tasarla.~Design transaction isolation separately from multi-node availability policy.~CAP'teki C ile ACID'deki C'yi aynı tutarlılık tanımı zannetme.~Do not conflate CAP consistency with ACID consistency.~Yerel atomicity küresel availability sorunlarını kendiliğinden çözmez.~Local atomicity does not automatically solve global availability.~Bölünme testi, staleness ve transaction rollback sonuçlarını kıyasla.~Compare partition tests, staleness, and transaction rollback results.
algo~basic~Array ve linked list~Arrays and linked lists~Array indeksleme ve cache locality sunar; linked list düğüm pointer'larıyla bağlantıyı yönetir.~Arrays support indexing and locality; linked lists link nodes via pointers.~Rastgele okuma ağırlıklı yükte array'i, gerçekten gerekli O(1) node removal durumunda listeyi değerlendir.~Prefer arrays for random reads; consider linked lists for genuine O(1) known-node removals.~Linked list'e node bulma maliyetini dahil etmeden O(1) silme garantisi verme.~Do not call deletion O(1) without accounting for locating the node.~Insertion semantiği ile cache dostu dolaşım arasında ödünleşim vardır.~Insertion semantics trade against cache-friendly traversal.~İndeks erişimi, allocation ve traversal benchmark sonuçlarını incele.~Inspect indexed lookup, allocations, and traversal benchmarks.
algo~basic~Hash table çakışmaları~Hash tables and collisions~Hash tablosu hash'i bucket'a eşler; collision yönetimi ve load factor performansı etkiler.~A hash table maps hashes to buckets; collision handling and load factor affect performance.~İyi Equals/GetHashCode sözleşmesi kullan ve değişmeyen anahtar tercih et.~Use a correct Equals/GetHashCode contract and immutable keys.~Hash fonksiyonunun benzersiz anahtarlar için çakışmasız çalışacağını varsayma.~Do not assume a hash function produces no collisions for unique keys.~Ortalama O(1) erişim mümkündür; kötü dağılım worst-case'i bozar.~Average O(1) access is possible but poor distribution harms worst cases.~Load factor, collision oranı ve kötü niyetli giriş performansını test et.~Test load factor, collision rate, and adversarial-input performance.
algo~intermediate~Binary search invariants~Binary search invariants~İkili arama sıralı aralıkta her adımda aday alanı yarıya indirir; sınır invariant'ı doğruluk için esastır.~Binary search halves a sorted search interval; boundary invariants are essential to correctness.~[left,right) gibi net aralık semantiği seç ve loop invariant yaz.~Pick a precise interval convention such as [left,right) and write a loop invariant.~Orta nokta güncellemelerini rastgele yaparak sonsuz döngü veya off-by-one oluşturma.~Do not update boundaries casually and cause infinite loops or off-by-one errors.~O(log n) karşılaştırma iyi olsa da veri sıralama gereği maliyet doğurur.~O(log n) lookup is efficient but requires ordering or sorting work.~Boş, tek eleman, bulunmayan ve duplicate input testleri çalıştır.~Test empty, singleton, missing, and duplicate inputs.
algo~intermediate~Heap ve priority queue~Heaps and priority queues~Binary heap tepe elemanını O(1) gösterir; insert ve remove O(log n) sürer.~A binary heap peeks at the top in O(1) and inserts/removes in O(log n).~Scheduling ve top-k akışlarında uygun bounded priority queue kullan.~Use a suitable bounded priority queue for scheduling and streaming top-k.~Heap'i tamamen sıralanmış dizi sanma.~Do not assume a heap is a fully sorted array.~Priority erişimi ucuzdur; key bazlı keyfi silme ek yapı gerektirebilir.~Priority access is cheap; arbitrary key deletion may require auxiliary structures.~Queue uzunluğu ve enqueue/dequeue latency değerlerini ölç.~Measure queue length and enqueue/dequeue latency.
algo~intermediate~Graph BFS ve DFS~Graph BFS and DFS~BFS kenar maliyeti eşit grafikte kısa yolu bulabilir; DFS derin dalları keşfeder.~BFS can find shortest paths in unweighted graphs; DFS explores deep branches.~Visited set tut ve shortest-path şartında uygun BFS yaklaşımını seç.~Maintain a visited set and use BFS when unweighted shortest paths are needed.~Negatif ağırlıklı yol için BFS'yi genel Dijkstra alternatifi sanma.~Do not treat BFS as a general alternative to Dijkstra on weighted graphs.~BFS bellek tüketebilir; DFS call stack derinliği sınırına takılabilir.~BFS may consume memory; recursive DFS may hit stack limits.~Genişlik, maksimum derinlik ve ziyaret edilen düğüm sayısını izle.~Monitor frontier width, max depth, and visited-node counts.
algo~advanced~Dijkstra ve negatif ağırlık~Dijkstra and negative edges~Dijkstra negatif olmayan kenar ağırlıklarıyla en kısa yolları bulur; negatif kenarlar garantiyi bozar.~Dijkstra finds shortest paths with nonnegative edge weights; negative edges break its guarantee.~Negatif kenar varsa Bellman-Ford gibi uygun algoritmayı değerlendir.~Consider Bellman-Ford when negative edges are possible.~Dijkstra'nın her yönlü ağırlıklı grafikte doğru sonuç verdiğini söyleme.~Do not claim Dijkstra works correctly for every weighted directed graph.~Priority queue verimi, negatif ağırlık desteğiyle yer değiştirir.~Priority-queue efficiency trades against support for negative weights.~Negatif edge testi ve shortest-path doğrulama seti çalıştır.~Run negative-edge test cases and shortest-path validation.
algo~advanced~Topological sorting~Topological sorting~DAG üzerinde topological order her yönlü kenarın kaynağını hedefinden önce sıralar.~A topological order of a DAG places every directed edge source before its destination.~Dependency graph'ta cycle detection ekleyip güvenilir build sırası oluştur.~Add cycle detection for reliable dependency build orders.~Cycle içeren grafikte geçerli topological sıralama varmış gibi davranma.~Do not pretend a cyclic graph has a valid topological ordering.~Bağımlılık sırası açıklaşır fakat paralellik olan düğümler birden fazla geçerli sıra üretebilir.~Dependency ordering becomes explicit, but parallel nodes admit multiple valid orders.~Indegree kalan düğümleri ve cycle raporlarını kontrol et.~Inspect remaining indegree nodes and cycle reports.

os~advanced~File descriptor ve handle sınırları~File descriptors and handles~Dosya, socket ve pipe gibi kernel nesnelerine süreçler fd/handle aracılığıyla erişir.~Processes access kernel objects such as files, sockets, and pipes through descriptors or handles.~Handle'ları deterministik kapat, limit ve açılan kaynak sayısını izle.~Close handles deterministically and monitor limits and open resources.~GC'nin managed nesneyi toplamasını dosya tanıtıcısının hemen kapanmasıyla karıştırma.~Do not equate managed-object collection with immediate descriptor closure.~Açık kaynakların tutulması tekrar kullanım sağlar ama işletim sistemi limitlerini tüketir.~Keeping resources open enables reuse but consumes OS limits.~EMFILE, open handle count ve socket state metriklerine bak.~Track EMFILE errors, open handles, and socket states.
os~intermediate~Linux signal ve graceful stop~Linux signals and graceful shutdown~SIGTERM nazik kapatma isteğidir; SIGKILL hedef sürece cleanup fırsatı vermez.~SIGTERM requests graceful termination; SIGKILL gives the target no cleanup opportunity.~SIGTERM'i yakala, yeni iş kabulünü durdur ve in-flight işlemleri sonlandır.~Handle SIGTERM, stop new work, and drain in-flight operations.~SIGKILL gelince finally bloğunun kesin çalışacağını varsayma.~Do not assume finally will run after SIGKILL.~Graceful stop veri güvenliğini artırır ama shutdown süresi tüketir.~Graceful shutdown improves data safety but consumes time budget.~Termination grace period, açık istek ve tamamlanmamış mesajları takip et.~Monitor grace periods, open requests, and unfinished messages.
os~advanced~Container ve kernel paylaşımı~Containers and shared kernels~Container süreç izolasyonu için namespace/cgroup kullanır; host kernel'ini paylaşır.~Containers use namespaces and cgroups for process isolation while sharing the host kernel.~Resource limit ve security context'i ayarla; container'ı VM ile aynı izolasyonda sayma.~Set resource limits and security contexts; do not equate containers with VMs.~Konteyner sınırlarının host kernel açığını bütünüyle engellediğini varsayma.~Do not assume container boundaries completely prevent host-kernel exploitation.~Container hafiftir fakat VM'ye göre kernel izolasyonu daha sınırlıdır.~Containers are lightweight but offer less kernel isolation than VMs.~OOMKilled, throttling ve syscall audit'lerini kontrol et.~Inspect OOMKilled events, throttling, and syscall audits.
os~advanced~NUMA ve CPU affinity~NUMA and CPU affinity~NUMA mimaride bellek erişim süresi CPU soketine göre değişebilir; uzak bellek daha maliyetlidir.~In NUMA architectures, memory latency may vary by CPU socket; remote memory is costlier.~Yalnızca ölçüm gösteriyorsa CPU pinning veya NUMA-aware allocation uygula.~Apply CPU pinning or NUMA-aware allocation only when measurements support it.~Affinity ayarının her iş yükünde hızlanma sağladığını varsayma.~Do not assume affinity settings accelerate every workload.~Yerelliğin avantajı scheduler esnekliğini ve iş dengelenmesini azaltabilir.~Locality gains can reduce scheduler flexibility and load balance.~Remote memory access, cache miss ve tail latency ölç.~Measure remote memory access, cache misses, and tail latency.
os~intermediate~Filesystem durability ve fsync~Filesystem durability and fsync~write çağrısı verinin kalıcı medyaya kesin yazıldığı anlamına gelmez; fsync dayanıklılık sınırına yaklaşır.~A write call does not guarantee data has reached durable media; fsync requests persistence.~Kritik state için fsync, journal ve atomic rename semantiklerini tasarla.~Design fsync, journaling, and atomic rename semantics for critical state.~Write başarılı döndüğünde elektrik kesilmesine kesin dayanıklı olduğunu varsayma.~Do not assume a successful write survives sudden power loss.~Daha güçlü durability garantileri I/O latency maliyetine gelir.~Stronger durability guarantees raise I/O latency.~Crash injection testleri, fsync latency ve recovery loglarına bak.~Use crash-injection tests, fsync latency, and recovery logs.
os~advanced~Shared memory ve IPC~Shared memory and IPC~Process'ler pipe, socket veya shared-memory üzerinden haberleşebilir; paylaşılmış bellek ek eşzamanlama ister.~Processes communicate via pipes, sockets, or shared memory; shared memory requires explicit synchronization.~IPC seçerken ownership, serialization, failure isolation ve throughput'u birlikte değerlendir.~Evaluate ownership, serialization, failure isolation, and throughput when selecting IPC.~Shared memory kullanınca lock ve memory ordering gereksinimi kalkmaz.~Shared memory does not eliminate locks or memory-ordering requirements.~Sıfır kopya iletişim hızlıdır ama koordinasyon karmaşıklığı artar.~Zero-copy communication is fast but adds coordination complexity.~IPC latency, context switch ve veri yarışlarını profille.~Profile IPC latency, context switches, and data races.
